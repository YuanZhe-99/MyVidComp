# 安全模型

在转换和验证成功之前，MyVidComp 绝不替换源视频；在最终提交之前，绝不触及目标文件夹。

## 临时文件

- 长时间运行的 ffmpeg 写入进入 MyVidComp 自有的临时文件，命名 `.myvidcomp-<stem>-<timestamp>.tmp.mp4` 或 `.tmp.mkv`。
- 配置 `tmp_dir` 时，临时文件位于该本地目录（对 SMB/NAS 目标有用）；否则位于源文件旁。
- 缓存的 `.myvidcomp-<stem>-*.tmp.mp4` / `.tmp.mkv` 文件只有在同一验证路径通过后才可复用——绝不仅因文件存在。
- 不可读的 MyVidComp 临时输出，尤其是无可读视频流的文件，会被删除且不复用。只有匹配 MyVidComp 临时命名的文件才会被删除。

## 编码前的冲突检测

当输出路径、`.old` 路径、临时路径或 `.myvidcomp.recover` 路径已存在时，文件以冲突原因跳过。已存在的输出文件和 `.old` 文件绝不静默覆盖。

## 提交

- 提交仅在完整验证通过后发生。
- 验证通过的临时输出通过同目录重命名替换源文件；跨设备移动回退为带进度的复制。
- 使用 `--keep-original` 时，原始文件先改名为 `<name>.<ext>.old`。
- 最终提交临时路径位于目标旁，使最后一次重命名同卷。
- 恢复路径命名（`.myvidcomp.recover`）支持中断提交的人工恢复。

## 原始文件

测试绝不覆盖、删除或改名真实用户视频——测试使用合成夹具。在转换和验证成功之前，原始文件始终保留。

## 优雅停止

- CLI：输入 `q` 回车，再以 `y` 确认。
- 确认提示激活期间暂停进度刷新。
- 活动的 ffmpeg 进程绝不中断；MyVidComp 完成当前文件后，在开始下一个文件前停止。
- 嵌入 API 通过 `CancellationToken::request_stop` 取消，语义相同。

## 配置

`config.yaml` 是用户所有的输入：MyVidComp 按需读取，但从不重写或规范化它。GUI 将自身偏好存储在用户配置目录，且不得重写 `config.yaml`。

# 应用程序

`gui/` 下的应用程序内嵌转换引擎，用同一套源码为 Windows、macOS、Linux 和 Android 构建。它通过
[ffi-abi.md](ffi-abi.md) 中的 ABI 驱动引擎，消费结构化事件，而不是解析终端输出。

## 界面

四个页面，按人们遇到它们的顺序排列：

| 页面 | 内容 |
|---|---|
| 转换 | 文件夹、输出编码、画质目标、严格程度，以及「开始」。 |
| 进度 | 当前正在发生什么、汇总数字、每个已完成的文件，以及可折叠的技术日志。 |
| 待你决定 | 等待决定的转换，附带分数、大小和改动内容。 |
| 设置 | 其余一切，不常用的部分收在「高级」里。 |

只要有待决定的项目，「待你决定」这一项就会带上角标。

## 布局

P2 使用公共导航绘制，保留下方宽度规则和审核角标。
内容位置在缩放时保持稳定，见 [shared-ui.md](shared-ui.md)。

一套布局，三种宽度，依据窗口而不是设备来选择：

| 宽度 | 导航 | 选项 |
|---|---|---|
| 小于 600 | 位于底部 | 下拉框 |
| 600 到 1100 | 侧边导航栏，图标加标签 | 放得下时用分段按钮 |
| 1100 及以上 | 侧边导航栏展开 | 分段按钮 |

页面内容限制在便于阅读的宽度内并居中，因此最大化窗口不会把表单横向拉满整个屏幕。所有列表都可滚动，
不会有任何元素因尺寸固定而被截断。

## 用词

引擎自身的取值，例如 `hevc`、`flexible` 和 `mkv-fallback`，永远不会显示出来。每一个都有标签，需要
解释的选择还配有一句说明，讲清楚选它意味着什么。编码器名称是被描述而不是被打印出来的：`av1_nvenc`
读作 NVIDIA 显卡。

四种语言均已完整翻译：英语、简体中文、繁体中文和日语。语言选择器可以跟随设备。测试会断言在每种语言
中，每个选项的标签都与它的传输值不同。

## 运行方式

- 转换在工作 isolate 中进行，因此界面保持响应。列出待复核项在一个短暂存在的独立 isolate 中进行，因此
  庞大的文件夹树也不会让界面卡住。
- 进度列表和日志列表通过只创建一次的视图读取，而不是每画一行就复制一次；一个引擎事件只让画面重绘一次。
  文件按完整路径区分，因此两个各自含有 `clip.mp4` 的文件夹会各得一行。
- Windows 文件夹对话框以 UTF-8 返回路径，因此任何语言命名的文件夹都能完整返回。
- 界面要求 ABI 版本 1 或更新，引擎缺失或不匹配时会明确报告，而不是在启动过程中崩溃。
- 停止是优雅的：正在运行的 ffmpeg 绝不会被打断，运行会在当前文件结束后停下。
- 取消令牌在每条路径上都会被释放，包括 isolate 被强制结束时。
- 引擎启动的每个 `ffmpeg` 和 `ffprobe` 进程都走共享的构造器，因此 Windows 上绝不会闪出命令行窗口。
  界面出于同样的原因不得重新引入直接的 `-version` 检查：在 Windows 上它改为检查文件是否存在，而不是
  运行它。

## 界面风格

Expressive 实现现在通过 MyApps-UI `v0.1.0` 共享；
应用保留基础主题。见 [shared-ui.md](shared-ui.md)。

设置中除了浅色、深色和跟随设备的外观之外，还提供两种界面风格：**Material 3**，即应用自己的 Material 3
主题；以及默认的 **Expressive**。Expressive 就是在同一主题之上叠加一层主题级别的 Material 3 Expressive
近似效果（`gui/lib/app_theme.dart`）：对话框、面板、菜单、Chip、输入框和浮动操作按钮采用更大的圆角；
消息条浮动显示；按钮静止时为胶囊形、按下时变为圆角方形；显示、标题类文字更粗；采用 2024 版进度指示器和
滑块样式；以及淡入前进式页面转场。两种风格使用相同的种子色和配色方案，保留现有的卡片与输入框定制，
布局完全相同。Flutter 没有 Expressive 组件，因此弹簧动效、波浪形指示器和按钮组不做模仿。没有导航栏选项：
两种风格下应用的导航相同。

## 设置

- 以 `settings.json` 保存在用户配置目录中，Windows 和 macOS 上位于 `MyVidComp` 下，其他系统位于
  `myvidcomp` 下。绝不写入属于用户的 `config.yaml`。
- 保存时先在 `settings.json` 旁写入一个临时文件，再改名到位，因此写到一半时崩溃也不会留下写了一半的
  设置文件。
- 上一版写下的设置文件会被读取一次，因此已有安装能保留自己的文件夹、工具路径和语言。已停用的转换模式
  取值会被映射到编码器偏好上。
- 风格以 `uiStyle` 保存（`material3` 或 `expressive`；缺失或无法识别时为 `expressive`），与 `themeMode`
  并列。
- 存储的取值未知或超出范围时，会退回默认值，而不会传给引擎。
- 视频工具会在应用程序旁边、同级的 `bin/` 目录、工作目录和 `PATH` 中查找。设置中给出的路径优先。

## 进度

两条进度条：当前文件一条，整个运行一条，两条都是确定的。文件经过的每一个阶段都会报告进展，包括
挑选画质设置和测量结果，因此只有扫描文件夹时才是不确定的。两条进度条都不会倒退，空闲时也绝不会
停留在未知状态。

运行进度条会计入这次运行处理完的每一个文件，跳过的也算在内，所以对已经转换过的文件夹再跑一次，
进度依然会走到头。

文件进度条旁边显示阶段、FFmpeg 报告的速度和剩余时间；详情日志的每一行也带有它的严重程度。

## 标识

Windows 可执行文件为 `MyVidComp.exe`，窗口标题和产品元数据为 `MyVidComp`，图标由同一张源图为所有
平台生成。

## 构建

Windows 构建通过 CMake 编译引擎，并把 `myvidcomp_core.dll` 安装在可执行文件旁边。视频工具单独随包
提供；参见 [packaging.md](packaging.md)。Android 构建见 [android.md](android.md)。
